두 스킬은 **각자의 저장소**에 있어요. 늘 최신 버전이라 여기서 링크로 바로 가시면 됩니다.

## 🧽 1. 스폰지 GTM 코어

> **github.com/selfishclub/sponge-gtm-core**
> → **[바로 가기](https://github.com/selfishclub/sponge-gtm-core)**

### 뭘 해주나요

**뭘 파는 건지부터 정리해주는 스킬**이에요. 클로드가 열네 개쯤 질문을 하나씩 던지고, 답하다 보면 **문서 한 장**이 나옵니다.

> **"우리는 드릴을 파는 것이 아니라, 벽에 뚫린 구멍을 판다."**

네 블록으로 되어 있어요.

| | 블록 | 무엇 |
|---|---|---|
| **A** | **재료** | 내가 이미 가진 것 |
| **B** | **고객이 내 비즈니스를 통해 느끼는 변화** | 내가 무엇을 바꾸는가 |
| **C** | **주요 가치** | 그 사람이 왜 이걸 택하는가 |
| **D** | **주요 페르소나** | 그 변화를 사는 사람 한 명 |

**아이템은 정하지 않아요.** 아이템은 가장 자주 바뀌는 거라 맨 마지막입니다.

### 이럴 때 씁니다

- *"내가 뭘 파는 건지 모르겠어"*
- *"주요 가치 잡아줘"* · *"페르소나 정해줘"*
- *"아직 아이템이 없는데요"* ← **이때가 제일 필요한 순간이에요**

### 설치

**클로드 코드**

```bash
git clone https://github.com/selfishclub/sponge-gtm-core.git ~/.claude/skills/sponge-gtm-core
```

**클로드 앱** — 저장소에서 `sponge-gtm-core.skill` 내려받아 → **Customize → Skills → + → Create skill → Upload a skill**

### 설치했으면

그냥 말을 걸면 됩니다.

```
GTM 코어 잡아줘
```

## 🔍 2. 가상 고객 피드백 & QA

> **github.com/selfishclub/virtual-customer-feedback-qa**
> → **[바로 가기](https://github.com/selfishclub/virtual-customer-feedback-qa)**

### 뭘 해주나요

**세운 코어를 가상 고객 5명한테 부딪혀보는 스킬**이에요.

NVIDIA가 공개한 **한국인 합성 페르소나 데이터**(통계에 정렬된 100만 명)에서 사람을 불러와서, *"쓸 것 같은지, 왜 안 쓸 것 같은지"* 를 묻습니다.

패널은 이렇게 짜여요.

```
핵심 사용자 2  +  경계 사용자 2  +  비사용자 1  =  5명
```

> **경계 사용자가 핵심이에요.** 핵심만 부르면 다 좋다고 하고, 비사용자만 부르면 다 싫다고 합니다.
> **타깃의 진짜 경계선은 경계 사용자에게서 드러나요.**

### 이럴 때 씁니다

- *"이 가격이면 살까?"*
- *"누가 안 쓸까?"*
- *"랜딩페이지 테스트해줘"*
- *"어디서 막히는지 봐줘"* ← 실제로 눌러보게 시키는 QA 모드도 있어요

### 설치

**데이터 파일이 있어서 조금 커요 (약 15MB).** 클론을 권합니다.

```bash
git clone https://github.com/selfishclub/virtual-customer-feedback-qa.git ~/.claude/skills/virtual-customer-feedback-qa
```

### ⚠️ 쓸 때 두 가지만

| | |
|---|---|
| **① 실제 검증을 대체하지 않아요** | 진짜 고객 앞에 서기 전에 **큰 실수를 걸러내는 자리**예요 |
| **② 비율로 말하지 않아요** | *"40%가 이탈합니다"* ❌ → *"이 지점에서 막히는 사람이 있습니다"* ⭕ |

## 두 스킬은 이어져 있어요

```
sponge-gtm-core          →   virtual-customer-feedback-qa
코어를 세운다                  세운 걸 짚어본다
```

**GTM 코어가 만드는 세 칸이, 검증 스킬이 받는 세 개와 그대로 맞물립니다.**

| 검증 스킬이 받는 것 | ← GTM 코어의 어느 칸 |
|---|---|
| 프로덕트 한 줄 설명 | **B · 한 문장** |
| 타깃 고객 | **D · 주요 페르소나** |
| 대상물 | **C · 주요 가치** |

**코어를 세우면 검증 스킬 브리핑이 이미 끝나 있어요.** 따로 준비할 게 없습니다.

반대로 코어 없이 검증부터 하면 *"타깃이 누구예요?"* 에 *"음… 다요"* 라고 답하게 돼요. **순서가 있는 이유입니다.**

### 넘길 때 쓰는 프롬프트

```
방금 만든 GTM 코어로 가상 고객 피드백 받아보고 싶어.

한 문장: (B의 한 문장)
페르소나: (D 내용)
가치: (C의 2패스 문장)

핵심 2 · 경계 2 · 비사용자 1로 패널 짜서
쓸지 안 쓸지, 왜 그런지 물어봐줘.

내가 놓친 지점이 있으면 그걸 중심으로 정리해줘.
```

> **전체를 바꾸려고 돌리는 게 아니에요.**
> ***"어 이건 생각 못 했네"* 싶은 지점이 하나라도 나오면 그걸로 충분합니다.**

## 결과가 나오면 이렇게 읽어요

| 검증에서 이렇게 나오면 | 이 칸을 한 번 더 봅니다 |
|---|---|
| ❌가 많고, 거절 이유가 *"나랑 상관없는 얘기"* | **D · 페르소나** — 내가 생각한 사람이 맞나 |
| 🔺가 많고, **요구하는 게 다들 같은 것** | **C · 가치** — 그 조건이 진짜 이유일 수 있어요 |
| ⭕인데 **"지인에게 설명한다면"이 제각각** | **전달** — 코어는 그대로, 말이 안 잡힌 것 |

**세 번째가 특히 유용해요.** 답이 다섯 명 다 다르면 내 말이 안 잡혔다는 뜻이고, **그 답들이 그대로 카피 재료**가 됩니다.
