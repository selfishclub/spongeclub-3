# 레저로 스크린파크골프 창업상담 랜딩

스크린파크골프 창업을 검토하는 사람이 레저로의 규모·기술을 확인하고
그 자리에서 상담을 신청하는 **한 장짜리 랜딩 페이지**입니다.

- 화면은 한 장. 위에서 아래로 스크롤합니다. 다른 페이지로 가는 라우팅은 없습니다.
- 폼을 제출하면 **폼이 있던 자리**가 "접수되었습니다" 안내로 바뀝니다.
- 상담 문의는 Supabase `inquiries` 테이블에 저장됩니다.

Next.js (App Router) · Supabase · Vercel

---

## 배포 전에 반드시 할 일

### ⚠️ 1. 대표전화 번호 교체

`lib/config.ts` 의 `TEL` 이 아직 가짜 번호입니다.

```ts
TEL: '032-000-0000',   // ← 실제 번호로 바꾸세요
```

전화번호는 코드 어디에도 따로 쓰여 있지 않습니다. **이 한 줄만 바꾸면 됩니다.**

### 2. Supabase 프로젝트 만들고 테이블 준비

1. https://supabase.com 에서 프로젝트를 만듭니다.
2. 왼쪽 메뉴 **SQL Editor** 로 들어갑니다.
3. `supabase/migrations/20260821000000_create_inquiries.sql` 파일 내용을
   **전부 복사해서 붙여넣고 Run** 합니다.

이 SQL 하나가 테이블·제약조건·인덱스·RLS 정책을 모두 만듭니다.
여러 번 실행해도 안전합니다.

### 3. 환경변수 넣기

Supabase 프로젝트의 **Settings → API** 에서 두 값을 복사합니다.

| 환경변수 | 어디서 복사 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Project API keys 의 `anon` `public` |

> `service_role` 키는 **절대** 넣지 마세요. 그 키는 RLS 를 통째로 우회합니다.
> `anon` 키는 공개되어도 되는 값입니다. 실제 보호는 아래 RLS 정책이 합니다.

**로컬에서 볼 때** — `lezuro/.env.local` 파일을 만들고 두 줄을 넣습니다.
(`.env.example` 을 복사해서 쓰면 편합니다.)

**Vercel 에 배포할 때** — 프로젝트 Settings → Environment Variables 에 두 값을 등록합니다.
`NEXT_PUBLIC_` 으로 시작하는 값은 **빌드 시점에 박히므로**, 값을 바꾸면 다시 배포해야 합니다.

### 4. Vercel 배포

이 저장소는 랜딩 페이지 전용 저장소가 아니라서, **Root Directory 를 지정해야 합니다.**

1. Vercel 에서 New Project → 이 저장소 선택
2. **Root Directory** 를 `lezuro` 로 설정 ← 이 단계를 빠뜨리면 빌드가 실패합니다
3. Framework Preset 은 Next.js 로 자동 인식됩니다
4. 위 3번의 환경변수 2개를 등록하고 Deploy

## 상담 문의는 어디서 보나요

방문자는 남이 남긴 문의를 **읽을 수 없습니다** (RLS 로 막혀 있습니다).
관리자는 이렇게 봅니다:

- Supabase 대시보드 → **Table Editor** → `inquiries` 테이블

문의 확인용 관리자 페이지는 v1 범위 밖입니다 (`prd-v3-admin.md` 로 분리).

---

## Supabase RLS — 무엇을 막고 있나

`inquiries` 테이블은 RLS(행 수준 보안)가 켜져 있습니다.
**정책으로 허용한 것 외에는 전부 막힙니다.**

| 누구 | INSERT (문의 남기기) | SELECT (문의 읽기) | UPDATE / DELETE |
|---|:---:|:---:|:---:|
| `anon` (사이트 방문자) | ✅ 허용 | ❌ 차단 | ❌ 차단 |
| `authenticated` (로그인 사용자) | ✅ 허용 | ❌ 차단 | ❌ 차단 |
| `service_role` (관리자·대시보드) | ✅ | ✅ | ✅ |

조회 정책을 "만들지 않는 것"이 곧 조회를 막는 방법입니다.
방문자가 남의 이름·연락처를 긁어가지 못합니다.

권한은 두 겹으로 걸려 있습니다. 둘 다 통과해야 동작합니다.
- **RLS 정책** — 어떤 *행*을 다룰 수 있는가
- **GRANT** — 애초에 그 *테이블*에 무슨 동작을 할 수 있는가 (`anon` 에게는 `INSERT` 만 부여)

입력값은 세 군데에서 검증합니다.
- 브라우저 — 동의 전에는 제출 버튼이 비활성
- 서버 액션 (`app/actions.ts`) — 우회 요청도 다시 검사
- 데이터베이스 — 공백·길이 초과를 `CHECK` 제약으로 차단

## 자주 바꾸는 값

전부 **`lib/config.ts` 한 파일**에 모여 있습니다. 코드 다른 곳을 열 필요가 없습니다.

| 값 | 설명 |
|---|---|
| `TEL` | 대표전화 |
| `EMAIL` | 문의 이메일 |
| `REPLY_DAYS` | "영업일 기준 O일 이내" 의 O |
| `HERO_HEADLINE` / `HERO_SUB` | 첫 화면 문구 |
| `STAT_USERS` / `STAT_STORES` / `STAT_EVENTS` | 숫자 3개 |
| `FORM_OPEN` | `false` 로 바꾸면 폼 대신 마감 안내가 뜹니다 |
| `FORM_CLOSED_MSG` | 마감 안내 문구 |

매장 목록은 `lib/stores.ts`, 매장 사진은 `public/stores/` 에 있습니다.
(자세한 내용은 `public/stores/README.md`)


## 화면 구성 (위에서 아래로)

1. 히어로 — 로고 · 헤드라인 · 상담 신청 버튼
2. 숫자 3개 — 이용자 / 매장 / 대회 (화면에 들어오면 0부터 카운트업)
3. 왜 지금인가 — 시장·날씨·본사지원
4. 압도적 격차 — 경쟁사 이용자 수 막대 그래프
5. 매장 갤러리 — 가로 스크롤 카드
6. 기술 — 레저로펏 · P-핸디 · 네트워크 · AI · 코스
7. 본사 지원 — 대회 · 마케팅 · 업데이트 · 지사
8. 타사 비교표 — 10개 항목 (모바일에서는 표만 가로 스크롤)
9. **상담 폼** — 제출하면 이 자리가 완료 안내로 바뀝니다
10. 푸터 — 법인 정보

## 만들 때 지킨 것

- 본문 글자 **18px** 아래로 내리지 않음 (주 고객층이 50~60대)
- 페이지에 가로 스크롤이 생기지 않음 — 표와 갤러리는 자기 영역 안에서만 스크롤
- `prefers-reduced-motion: reduce` 인 사용자에게는 애니메이션을 전부 끔
- 개인정보 동의 없이는 제출 불가
- 자주 바뀔 값은 `lib/config.ts` 한곳에 (v3 어드민을 붙일 자리)
